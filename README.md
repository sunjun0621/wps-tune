# WPS Tune — WPS Office 启动优化工具(单文件 BAT)

一个 **BAT 文件**搞定 WPS Office 的启动优化与日常维护:下载 [`WPS优化.bat`](WPS优化.bat) 双击即用,自动探测本机 WPS 安装位置,**不绑定路径与版本**,可拷到任意装了 WPS 的 Windows 电脑。

> 结论先行:WPS 启动慢的头号原因是云服务进程 `wpscloudsvr.exe`。
> 实测在 Windows 10/11 + WPS 12.1 上,它每次启动独占约 6 秒 CPU 和 250 MB 内存,
> 约占整个启动开销的一半。本工具的「一键优化(含云服务)」实测把启动 CPU 从 10.9s 降到 3.4s、
> 内存从 795MB 降到 546MB。

## 使用方法

1. 下载本仓库里的 **`WPS优化.bat`**(右键另存,只需这一个文件)
2. 双击运行 → 自动请求管理员权限(UAC 拒绝也可以用只读功能)
3. 按菜单数字操作,写操作都会先列计划、确认后才执行

## 功能(菜单 7 项)

| 菜单 | 功能 | 说明 |
|---|---|---|
| [1] 体检诊断 | 只读 | 版本 / 所在磁盘类型 / 进程 / 云服务状态 / 旧版本与旧插件 / 云盘缓存(逻辑大小 vs 真实占用)/ 强制登录 / 使用记录 |
| [2] 一键优化 | 可逆 + 清理 | 关闭 WPS → 删旧版本目录、被新版本取代的旧插件、旧插件清单 → 清空 cache/log → 禁用 WpsWake* 登录唤醒任务 → 修复 SysMain 与预读参数;**云服务禁用需单独确认**(收益最大) |
| [3] 撤销优化 | 可逆 | 恢复云服务、重新启用已禁用的 WPS 计划任务 |
| [4] 清理缓存 | 清理 | 缓存 / 日志 / 临时残留 / 崩溃转储;被占用的文件跳过,不卡流程 |
| [5] 免登录 | 可逆 | 关闭/恢复强制登录引导:未登录也能用编辑、格式刷、粘贴、求和等基础功能(AI 与云文档仍需登录) |
| [6] 重置记录 | 自动备份 | 清最近文件 / 历史 / 开始页推荐 / 引导弹窗标记 / 界面布局等 23 处注册表 + 9 个目录,回到接近「刚安装」的状态 |
| [7] 还原记录 | 可逆 | 从最近一次备份恢复使用记录(manifest 逐项还原) |

已执行的可逆动作记录在脚本同目录的 `wps-tune-state.json`;重置记录的备份在 `backups\profile-<时间戳>\`,带 `manifest.json`。

## 保护区(代码硬校验)

以下路径在任何清理动作里都会被**直接拒绝**(`Get-ProtectedPaths` / `Test-ProtectedPath` 双重校验):

- **文档自动备份**(`NewBackupPath`,里面可能是未保存文档的副本,最不能碰)
- **云盘缓存**(`CurrentWpsCloudCachePath` —— 逻辑大小看着几十 GB,其实几乎全是「按需下载」的占位文件,删了等于丢掉整个云盘入口)
- **模板**(`templates`)

## 注意事项

- **禁用云服务的代价**:云文档无法在 WPS 客户端内直接打开;本地 docx/xlsx/pptx/pdf **完全不受影响**(已实测)。菜单 [3] 一键还原。
- **WPS 升级后可能失效**:升级会重新生成 `wpscloudsvr.exe`,重跑一次 [2] 即可。
- **机械盘是硬伤**:诊断会明确提示;把 WPS 迁到 SSD 的收益大于任何调优。
- 免登录若改完功能区仍是灰的,再勾一步:WPS 内 `配置和修复工具 → 高级 → 其他选项 → 兼容离线状态下的未登录使用方式`。

## 兼容性

- Windows 10 / 11(内置 PowerShell 5.1,无需额外运行环境)
- WPS Office 12.x(按注册表与路径模式探测,11.x 及更早可能路径不同)
- 修改计划任务、服务、Program Files 下的文件需要管理员权限,非管理员时对应步骤会提示

## 技术实现

单文件 = ASCII 外壳 + 内嵌 PowerShell 段:运行时把 `rem #PS-BEGIN` / `rem #PS-END` 之间的脚本提取为带 BOM 的临时 ps1 执行(规避 cmd 中文编码问题),用完即删。安装探测只读注册表 `InstallRoot`、卸载项与常见默认路径,不写死任何位置。脚本无联网行为。

## 免责

脚本只做文件改名、删除冗余数据、开关计划任务/服务与注册表键这类常规操作,不含任何联网行为。建议先跑 [1] 体检诊断 看清现状,再决定是否执行写操作。
